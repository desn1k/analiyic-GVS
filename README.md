# Аналитика качества ГВС

Веб-приложение для анализа качества горячего водоснабжения (ГВС) по приборным
данным и отчётам. Backend — FastAPI + SQLite, frontend — React (Vite).

Развёртывание описано в [DEPLOY.md](DEPLOY.md). Ниже — **инструкция для новичка**:
что загружать, как всё связано и как пользоваться отчётом качества.

---

## 1. Что загружать (5 типов файлов)

Всё загружается одной кнопкой **«+ Загрузить отчёт (xlsx)»** — приложение само
определяет тип файла по его содержимому. Порядок загрузки не важен.

| Файл | Что это | Куда идёт |
|---|---|---|
| **Недельный отчёт качества ГВС** | агрегированный отчёт по объектам за неделю | основная база (`gvs.db`) |
| **Ведомость учёта параметров потребления тепла в системе ГВС** | почасовые данные с приборов (T1, T2, объём V) | приборная база (`device.db`) |
| **Ведомость отключений** | плановые/аварийные отключения ГВС | приборная база |
| **Реестр объектов** (паспорта АИИС) | справочник объектов: система, расч. температуры, нагрузки, ссылки | приборная база |
| **Сводный отчёт по поиску конечного источника** | иерархия: потребитель → ЦТП/ТК → источник | приборная база |

Крупные приборные файлы (до ~1.5 ГБ) разбираются в фоне — после загрузки в
статусе видно прогресс; страница сама обновится по завершении.

### Как данные связываются между собой
UUID-ы в разных системах не совпадают, поэтому связи такие:
- **Отключения → объект**: по ФИАС через реестр (`отключение.ФИАС → реестр → object_id`),
  запасной вариант — по адресу.
- **Реестр → точка учёта**: по `object_id` (совпадает с отчётом).
- **Иерархия → потребитель**: по `tu_id` точки учёта.
- **Приборные часы → точка**: по `tu_id` (UUID точки учёта).

Повторная загрузка **не дублирует** данные: часы перезаписываются по «точка+время»,
отключения — по «номер+адрес+дата+тип», реестр/иерархия — по id, отчёт — по периоду.

## 2. Разделы интерфейса

- **📊 Дашборд** (кнопка в шапке) — сводка: сколько точек, часов, достоверность,
  отключения, паспорта, а также списки: точки без данных, с пустыми данными и
  **точки иерархии без приборных данных**. Здесь же кнопка «Очистить приборные данные».
- **Динамика во времени / Сводка по неделям / Сравнение объектов по неделям** —
  анализ по **недельному отчёту** (агрегированные данные).
- **Анализ качества ГВС (приборные данные)** — расчёт некачества по **почасовым**
  приборным данным (см. раздел 3).
- **Точки учёта** — все точки из базы ГВС. Клик по названию объекта открывает окно
  с графиком: температура подачи/обратки, объём, зоны норматива (красная <40,
  жёлтая 40–60, зелёная 60–75 °C), вертикальные зоны отключений с причиной,
  **zoom** (ползунок снизу) и **иерархия** — можно наложить линии вышестоящих ТУ
  или переключиться на их график.

## 3. Отчёт «Анализ качества ГВС (приборные данные)»

Главный аналитический инструмент. Считает некачество ГВС из почасовых приборных
данных по нормативу СанПиН.

### Как пользоваться (пошагово)
1. Убедитесь, что загружены: **приборные данные** (обязательно), а для полноты —
   **ведомость отключений**, **реестр**, **иерархия**.
2. В блоке «Анализ качества ГВС» задайте параметры:
   - **С / По** — период анализа (дата и часы, вручную). Анализ ведём по неделям.
   - **Хроническое, %** — порог, выше которого нарушение считается хроническим (по умолч. 50).
   - **Достоверность, %** — минимальная доля достоверных часов, чтобы выносить
     вердикт (по умолч. 52). Ниже — «Недостаточно достоверных данных».
   - **Охват** — «База ГВС (точки учёта)» (по умолчанию, только контролируемые ТУ)
     или «Все приборные точки» (включая ЦТП/источники).
   - **Исключать часы без водоразбора** — часы с нулевым объёмом (стоячая вода) не
     учитываются (рекомендуется вкл.).
   - **Только с нарушениями** — показывать только проблемные точки.
3. Нажмите **«Анализ»** — появится таблица.
4. Нажмите **«⬇ Скачать отчёт (xlsx)»** — выгрузка в Excel с теми же параметрами.

### Логика расчёта (норматив СанПиН 2.1.4.2496-09)
Норма подачи ГВС — **60–75 °C**, с допустимым снижением:
- **днём** (05:00–00:00) — до −3 °C → нарушение при **T1 < 57 °C**;
- **ночью** (00:00–05:00) — до −5 °C → нарушение при **T1 < 55 °C**;
- **перегрев** — всегда при **T1 > 75 °C**.

Из расчёта **исключаются часы**:
- недостоверные (в приборе стоит «-»);
- попавшие в интервалы **отключений ГВС** (там низкая температура ожидаема);
- (опционально) **без водоразбора** (объём ≈ 0).

Точка **не анализируется**, если по ней (и по всей её иерархии) нет ни одного часа данных.

### Определение причины недогрева (по иерархии)
Для недогрева сравниваются часы нарушения потребителя с ближайшей **вышестоящей ТУ**
(ЦТП/источник), у которой есть данные, в те же часы:
- если и вверху низко → **системная причина** (источник/сеть);
- если вверху норма, а внизу низко → **локальная** (внутридомовая/тупиковая ветка);
- если у вышестоящих ТУ нет данных → «причина не определена».
Плюс добавляется пометка «тупиковая ветка», если объект помечен таковым в отчёте.

### Столбцы отчёта (xlsx)
| Столбец | Смысл |
|---|---|
| **Объект** | название/адрес объекта (из недельного отчёта) |
| **ID объекта** | `object_id` объекта |
| **ID точки учёта** | UUID точки учёта (прибора) |
| **Часов всего** | всего часов в периоде |
| **Достоверных часов** | часы с корректным показанием |
| **Зачтено часов** | часы, попавшие в расчёт (после всех исключений) |
| **Исключено (отключения)** | часы, отброшенные из-за отключений ГВС |
| **Исключено (без водоразбора)** | часы с нулевым объёмом |
| **Достоверность, %** | доля достоверных часов |
| **Недогрев, ч** | часы ниже порога |
| **Перегрев, ч** | часы выше 75 °C |
| **% нарушения** | доля нарушений от зачтённых часов |
| **Сред. T подачи, °C** | средняя температура подачи по зачтённым часам |
| **Вердикт** | Норма / Недогрев / Перегрев / хроническое / Недостаточно данных |
| **Причина** | системная / локальная (из анализа иерархии) |

## 4. Частые вопросы

- **Загрузил файл, а данные не изменились.** Пересоберите фронтенд и обновите
  страницу с очисткой кэша (Ctrl+Shift+R). Крупные приборные файлы парсятся минутами.
- **Отключения/причины не отображаются.** Нужны загруженные **реестр** (даёт связь
  ФИАС↔object_id) и **ведомость отключений**; проверьте счётчики в Дашборде.
- **Начать с чистого листа.** Дашборд → «Очистить приборные данные» (удаляет часы,
  точки, отключения, реестр, иерархию; недельные отчёты не трогает).

Обновление на сервере и настройка окружения — см. [DEPLOY.md](DEPLOY.md).
